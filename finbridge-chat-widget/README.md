# FinBridge Chat Widget

A **plug-and-play, embeddable AI chat widget** (RAY-style) for the FinBridge AI backend.
Drop **one `<script>` tag** into any website — plain HTML, React, Vue, WordPress, Shopify,
anything — and you get a floating launcher button that opens a chat panel wired to your
existing `POST /ai/chat/message` endpoint.

- 🧩 **Zero runtime dependencies** — one self-contained `.js` file (~15 KB gzipped).
- 🛡️ **Shadow DOM isolated** — the host page's CSS can't break it, and it can't break the host page.
- 🎨 **Themeable** — colors, copy, logo, suggestions, position.
- 🔌 **Doesn't touch your backend** — it only *calls* the API you already have.

---

## 1. Build it

```bash
cd finbridge-chat-widget
npm install
npm run build        # → dist/finbridge-widget.js
```

Other scripts:

| Command | What it does |
|---|---|
| `npm run build` | Minified production bundle → `dist/finbridge-widget.js` |
| `npm run dev`   | Live demo at <http://localhost:5500/demo/> + rebuild on change |
| `npm run watch` | Rebuild on change (no server) |
| `npm run typecheck` | Type-check without emitting |

Then host `dist/finbridge-widget.js` anywhere static (your CDN, S3, the FinBridge
server's public folder, etc.).

## 2. Embed it

Add these two tags to any page, just before `</body>`:

```html
<script>
  window.FinBridgeChatConfig = {
    apiUrl: "https://your-finbridge-host.com",   // your backend base URL
    token:  "YOUR_BEARER_TOKEN",                 // see "Authentication" below
    title:  "FinBridge",
    launcherLabel: "Ask FinBridge",
    primaryColor: "#dc2626",
    suggestions: ["Accept Payments", "Make Payouts", "How do I integrate?"]
  };
</script>
<script src="https://your-cdn.com/finbridge-widget.js" async></script>
```

That's the whole integration. The widget auto-initialises from
`window.FinBridgeChatConfig`.

### Or initialise manually (e.g. inside a React app)

```html
<script src="https://your-cdn.com/finbridge-widget.js"></script>
<script>
  window.FinBridgeChat.init({
    apiUrl: "https://your-finbridge-host.com",
    getToken: () => myAuth.getAccessToken(),   // refreshes per request
  });
</script>
```

## 3. Authentication

Your backend protects `POST /ai/chat/message` with a **Bearer token**
(`Authorization: Bearer <jwt>`). Provide it in **one** of three ways:

| Option | When to use | Example |
|---|---|---|
| `token` | Quick test / trusted internal page | `token: "eyJ..."` |
| `getToken` | **Recommended.** App already has a token & can refresh it | `getToken: async () => store.token` |
| `tokenUrl` | Your own server mints short-lived tokens for visitors | `tokenUrl: "/api/chat-token"` (must return `{ "token": "..." }`) |

Get a token in dev from your existing login route:

```bash
curl -s -X POST https://your-host/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"..."}' | jq -r .token
```

> **CORS:** the widget runs on the host page's origin and calls your API cross-origin.
> Make sure that origin is in the backend's `CORS_ORIGINS` env var (the server already
> allows the `Authorization` header).

## 4. Configuration reference

| Option | Type | Default | Notes |
|---|---|---|---|
| `apiUrl` | string | — | **Required.** Backend base URL. |
| `token` / `getToken` / `tokenUrl` | — | — | Auth, pick one (see above). |
| `title` | string | `"FinBridge"` | Panel header. |
| `subtitle` | string | — | Optional tagline. |
| `launcherLabel` | string | `"Ask FinBridge"` | Floating button text. |
| `welcomeMessage` | string | friendly default | First assistant message. |
| `suggestions` | string[] | 3 defaults | Quick-reply chips; click sends them. |
| `placeholder` | string | `"Type your question here…"` | Input placeholder. |
| `footerText` | string | `"All responses are generated by AI"` | Disclaimer. |
| `logoUrl` | string | built-in icon | Image URL, inline `<svg…>`, or an emoji. |
| `primaryColor` | string | `"#dc2626"` | Brand color. |
| `position` | `"bottom-right"` \| `"bottom-left"` | `"bottom-right"` | Dock corner. |
| `offset` | number | `24` | Distance from edges (px). |
| `zIndex` | number | `2147483000` | Stacking order. |
| `autoOpen` | boolean | `false` | Open on load. |
| `persistConversation` | boolean | `true` | Keep the thread across page loads (localStorage). |
| `storageKey` | string | `"finbridge"` | localStorage namespace. |
| `onOpen` / `onClose` | () => void | — | Lifecycle hooks. |
| `onMessage` | (m) => void | — | Fires for each user/assistant message. |

## 5. JavaScript API

`window.FinBridgeChat` exposes:

```js
FinBridgeChat.init(config)   // mount (or remount) the widget
FinBridgeChat.open()         // open the panel
FinBridgeChat.close()        // close the panel
FinBridgeChat.toggle()       // toggle
FinBridgeChat.send("hi")     // open + send a message programmatically
FinBridgeChat.reset()        // clear the thread, start a new conversation
FinBridgeChat.destroy()      // remove the widget from the page
```

## 6. How it talks to your backend

```
[ host website ]
      │  user types / clicks a chip
      ▼
FinBridge widget  ──POST {apiUrl}/ai/chat/message──►  FinBridge AI server
  { message, conversationId? }                         (auth + memory + MCP tools)
      ◄────────── { reply, conversationId, ... } ──────┘
```

- The first reply returns a `conversationId`; the widget reuses it so the thread has memory.
- A `202`/`requiresBackground` response (heavy/slow query) is shown to the user as-is.
- **No existing FinBridge code is modified** — this project only consumes the public API.
